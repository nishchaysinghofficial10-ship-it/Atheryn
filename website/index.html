Persistent computational research engine · v2.1.0

Every conclusion leads back to a recorded experiment.

Give ATHERYN a research question and a budget. It keeps competing hypotheses, turns them into machine-checkable predictions, runs reproducible experiments, attacks its own conclusions, and stops with an explicit reason.

How a mission runs

From hypothesis to scoped conclusion

Each step is a state in a validated state machine. Every transition, decision and confidence change is appended to the mission log, and the mission checkpoints after every step.

  1. Form hypotheses

    FORMING_HYPOTHESES

    Competing hypotheses from the domain's templates, plus model proposals that pass schema and vocabulary checks.

  2. Design an experiment

    DESIGNING_EXPERIMENT

    Predictions become machine checks such as fastest_on or beats. The next action is scored against the budget.

  3. Execute

    EXECUTING

    Generated code runs in a confined subprocess. Its code, spec, results and output are stored for good.

  4. Analyze

    ANALYZING

    Verdicts pass the significance gate. Anything weaker is recorded as inconclusive.

  5. Criticize

    CRITICIZING

    The critic audits assumptions, surfaces contradictions and raises cautions.

  6. Replicate

    REPLICATING

    Seed + 1000, regenerated inputs, a separately spawned process, the same predictions.

  7. Falsify

    FALSIFYING

    Probe at twice the largest tested size and on regimes held out from every earlier round.

  8. Conclude

    COMPLETED

    Accepted with a recorded scope, or weakened. A dossier is written and the stop reason is explicit.

Acceptance needs all three: confirmed predictions, an independent replication, and a survived falsification probe.

What a result means

Status is promoted by evidence, never by generation

The rules below stop the loop where a system generates a claim, believes it, and then cites itself.

Epistemic ladder

Every claim carries an explicit status. Model output can enter only as a hypothesis or as speculation.

  • EXPERIMENTAL_RESULTproduced by ATHERYN's own measurements
  • FACTseeded prior knowledge only
  • HYPOTHESISproposed, not yet tested
  • SPECULATIONingested, untrusted, confidence ≤ 0.4
  • CONTRADICTEDsignificant evidence against

Significance gate

A timing difference counts as decisive only when it clears all three.

  • ≥ 5trials per side
  • > 3×the combined standard error separating the means
  • ≥ 10%relative margin between them

Anything weaker is inconclusive. No p-values: at these trial counts they would imply precision the data lacks. Exact counts, like edge relaxations, need no gate.

Three kinds of reproducibility

Kept separate on purpose, because they promise different things.

  • Exact Code, inputs, seeds, config, correctness and outputs match, verified by digest.
    always asserted
  • Statistical Performance relationships hold, judged only when the data supports it.
    asserted with --strict
  • Absolute timings Belong to one host at one moment.
    never asserted

The second domain was added to test whether the core was really domain-agnostic. Eleven core modules never name a domain, and a test asserts it. The work also exposed two architecture gaps, which are documented in docs/SECOND_DOMAIN.md and closed in v2.1.0.

Scope

What ATHERYN is not

  • A general autonomous scientist. It runs computational experiments in a registered domain.
  • A web researcher. It retrieves URLs you approve. It does not search, crawl or browse, and everything it retrieves is untrusted.
  • An unrestricted code runner. It executes only code generated from its own audited domain templates, never code written by a model or taken from the web.
  • An oracle. Generated prose is never evidence. A model may propose; proposals go through the same experimental pipeline as everything else.
  • Unsupervised. Autonomy means choosing which permitted action runs next, inside limits you set. There is no daemon and no background service.

Safety

Boundaries it keeps

  • Experiments run under user-space confinement: rlimits, python -I, a scrubbed environment with no credentials, a cwd jail, output caps and a timeout. Designs that exceed policy are rejected before a process exists.
  • Model output is parsed, schema-validated and mapped through a fixed domain vocabulary. No path leads from a provider response to a fact, an evidence item or a graph relation.
  • Retrieved pages must be https, pass address checks, stay under size caps and match allowed content types. Their claims stay SPECULATION.
  • Autonomy cannot create an action type, widen a limit, or use the network without a per-run flag. One mission has one writer.
  • Credentials live only in environment variables, and every logged string passes a redactor.

Quick start

Run a mission in four commands

No install step and no packages to fetch. Python 3.10 or newer is all it needs.

shell
git clone https://github.com/nishchaysinghofficial10-ship-it/Atheryn.git
cd Atheryn
python -m unittest discover -s tests

python -m atheryn init "Which sorting strategy wins under which input regime?" \
    --dir runs/demo --profile fast
python -m atheryn run    --dir runs/demo
python -m atheryn status --dir runs/demo
python -m atheryn report --dir runs/demo

cancelStop with a recorded reason

Known limitations

What has not been verified

Saying "unverified" is welcome here. The build fails if the documentation starts overclaiming.

Two domains only

Both computational and deterministic. It must not be used for wet-lab, medical, legal or financial research.

Timings are single-machine

Only within-run rankings mean anything. Relaxation counts do transfer.

Confinement is user-space

No network or filesystem namespacing.

The live LLM path is unverified

The provider call has never executed against a real API. Everything around it is tested with a stubbed transport.

General-web retrieval is unverified

The live path was proven only against an allow-listed host.

No exactly-once guarantee

A crash mid-action is recorded as interrupted for operator review, never guessed.

No capability is complete without evidence. A feature comes with a test; a claim comes with the command that produced it.
