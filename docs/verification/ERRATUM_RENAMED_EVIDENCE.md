# Erratum — shipped evidence edited by the v2.1.0 project rename

The v2.1.0 release published experiment evidence that no longer matched its
own record. Every schema-v2 experiment under `examples/` failed
`atheryn replay` with "experiment code changed since it was recorded". The
measurements were never wrong; the runner files beside them had been edited
after they ran. This note says what happened, what was restored, and what was
deliberately left alone.

## What happened

The project was called **ORIGIN** until the v2.1.0 release, when it was
renamed ATHERYN with a case-preserving find-and-replace (`origin` → `atheryn`,
`ORIGIN` → `ATHERYN`). The replace also ran over `examples/`, which is stored
evidence, not source.

Each generated runner hashes its own bytes into `code_digest` when it runs
(`sha256(run.py)[:16]`), so `result.json` still held the digests of the August
runners. Replay re-hashed the renamed file and correctly refused it.

Nothing caught this before release. The replay check needs a POSIX sandbox and
ran in only one CI job, the CI workflow on `main` did not parse until it was
fixed on the `web-frontend` branch, and no unit test checked shipped digests.

## How the cause was established

1. `atheryn-project.zip` (added in commit 5868c46) is byte-identical to the
   release tree but keeps file timestamps. Every file that contains the name
   is dated 2026-09-03 21:58:22 (archive local time). No file without the name
   carries that timestamp. The experiments' `stdout.log` files, the algobench
   `spec.json` files and the schema-v1 results keep their August dates, and
   tools that never name the project, such as `tools/normalize_paths.py`,
   keep an earlier one.
2. In the aligned module map in `docs/ARCHITECTURE.md`, every `atheryn/…` line
   sits exactly one column right of its neighbours, so the old name had six
   letters.
3. An exhaustive search of all 308,915,776 six-letter lowercase names, each
   substituted into `examples/flagship_run/experiments/exp_42d46105c8/run.py`,
   found exactly one that reproduces the recorded digest `eb2e942e5a5d0d14`:
   `origin`.
4. Reversing the substitution reproduces the recorded `code_digest` exactly
   for **28 of 28** schema-v2 runners.
5. The current generator, given each stored `spec.json` and recorded version,
   re-emits the shipped runner byte for byte. The rename changed the name and
   nothing else.

## What was restored

The original bytes of the 28 runners that record a `code_digest`:

| Mission | Experiments |
|---|---|
| `examples/flagship_run` | all 13 |
| `examples/graph_mission` | all 6 |
| `examples/autonomy_demo` | 2 |
| `examples/final_flagship_mission/baseline` | 1 |
| `examples/final_flagship_mission/atheryn_full` | 6 |

The restoration verifies itself: each file now hashes to the digest it
recorded when it ran. The restored runners therefore say
`Auto-generated by ORIGIN` and use the key `origin_version`. That is
intentional, because those bytes are the record. Nothing was re-run and no
`code_digest`, measurement, input digest or output digest was changed.

## What was not restored (disclosed, left as shipped)

The same rename edited 95 other files under `examples/`. Every edit replaced
the project name and nothing else, but no digest covers these files, so none
of them is byte-original any more:

| Files | Edit |
|---|---|
| 28 `result.json` | key `origin_version` → `atheryn_version` in `environment` and `config` |
| 13 graphbench `spec.json` | the same key |
| 6 `demo_run` `run.py` (schema v1, no digest) | name in the header |
| 8 `state.json`, 7 `state.json.bak`, 8 `project.json` | the version key; name in a few recorded notes |
| 6 `dossier.md`, 6 `timeline.md`, 3 `mission_control.html` | name in generated reports |
| 4 `events.jsonl`, 2 `claims.json`, `evidence_demo_summary.json` | name in logged text |
| `final_flagship_mission/PREREGISTRATION.json` | name in the `note` field only |
| `final_flagship_mission/EVALUATION_RESULTS.json`, `final_flagship_mission/README.md` | name |

The directory name `final_flagship_mission/atheryn_full` contains the name too.
It was probably `origin_full` before the rename, but nothing records it, so
that is not verified.

The replay claims in `docs/release/CLEAN_ROOM_VERIFICATION.md` and
`docs/release/RELEASE_CHECKLIST.md` were made for the 2.0.0 artifacts, before
the rename. They did not hold for v2.1.0 as published until this restoration.

## Guard

`tests/test_shipped_evidence.py` recomputes every shipped runner's digest
with `hashlib` alone and fails if any differs from its `result.json`, or if a
schema-v2 result has no digest at all. It runs on every platform, so an edit
to stored evidence now fails the ordinary test suite.

## Verify it yourself

```
python -m unittest tests.test_shipped_evidence
python -m atheryn replay --dir examples/flagship_run --exp exp_42d46105c8
sha256sum examples/flagship_run/experiments/exp_42d46105c8/run.py | cut -c1-16   # eb2e942e5a5d0d14
```

Recorded at this commit: the guard test passes, and replaying all 28
restored experiments reported "experiment code verified" with every input and
output digest verified. That replay ran on Windows 11 / CPython 3.15.0 with
the POSIX rlimit hook stubbed, as a local check only. The CI `portability` job
on Linux is the authoritative run.
